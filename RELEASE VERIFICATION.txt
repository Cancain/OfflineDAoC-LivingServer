OFFLINE DAOC 0.36 / 0.36b / 0.36c - VERIFICATION

Source and builds
- Server (Release build): 2,764 automated tests passed, 0 failed.
- Launcher: 107 automated tests passed, 0 failed.
- The release server is built from the development server's source (its
  newest commit) plus the edition switch: the two differ only in the four
  files that add classes / enable_sluaghbinder.
- 0.36 and 0.36b run the same server program. The 0.36 edition swaps only the
  world database (switch off; the Sluaghbinder trainer, wisp and 9 class skill
  rows removed) and the game client game.dll, so it has every bot and world
  fix of 0.36b.

Package checks (build_release_036.py)
- The runtime was copied 1:1 from a snapshot of the development install:
  31,916 files, each hashed. Logs, backups, accounts, dumps, DXVK and
  diagnostics switches are excluded.
- The world database passes SQLite quick_check. It has no accounts,
  characters, bots, inventories, houses or auctions. All 81 keeps have their
  original owner and level and all 421 keep doors are whole; relics are at
  home. GM is off, XP is 1x, the bot target is 0 and automatic account
  creation is on.
- The shipped world data: the 85 Darkness Falls raid spawns match the raid
  event file, the 162 quest kill targets respawn within 300 seconds, and the
  relic pad needs 8.
- The whole package was scanned for developer or test accounts, the test
  account file, DXVK and diagnostics files before sealing: none.

End-to-end smoke test (smoke_release_036.py), 0.36b and 0.36
- The launcher created the install's own account.txt.
- The server started using only the bundled .NET runtime.
- A login through connect.exe (as ENTER REALM does) made the server create a
  fresh 'offline' account at player level (enable_sluaghbinder True in
  0.36b, False in 0.36).
- The server shut down cleanly.

- The 0.36c package: 53,755 files (33.8 GB), in 19 independent zip parts of
